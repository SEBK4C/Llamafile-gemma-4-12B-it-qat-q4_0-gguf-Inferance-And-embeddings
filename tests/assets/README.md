# Multimodal upload test corpus

Generated by `tests/make_upload_assets.py` (regenerate any time — `say`,
Pillow, `cupsfilter`; ground truth in `manifest.json`). Two halves:

**Automated (API — same payloads the web UI sends):**
```sh
python3 tests/upload_ingest_probe.py          # against 127.0.0.1:8080
```
Covers: image→chat OCR/chart-reading, audio→chat native STT, document
text→`/v1/ingest` (enrichment + fidelity gate + 1024-dim vectors), and
retrieval sanity (manifest queries must hit their own document via
`/v1/embeddings`).

**Manual (web UI upload, drag each file into the composer):**

| file | drag into composer, then ask | expect |
|---|---|---|
| `pdfs/receipt.pdf` | "What was the total and the receipt number?" | EUR 108.40, R-88231 (UI extracts PDF text client-side) |
| `pdfs/policy.pdf` | "How many remote days per week?" | three days/week, EUR 500 approval threshold |
| `images/invoice.png` | "Invoice number and total due?" | INV-2047, EUR 385.00 |
| `images/chart.png` | "Which backend is fastest?" | CUDA at 105 tok/s |
| `images/sign.png` | "What does this say?" | CAUTION / server room 42B |
| `audio/receipt-total.wav` | (attach, no text) "Transcribe this." | "…forty seven dollars and twenty cents." |
| `audio/meeting-date.wav` | "When is the meeting?" | March 12th, 10:30 |
| `audio/fox-pangram.wav` | "Transcribe." | the pangram, verbatim |

Also worth a manual pass while you're there: 🎙 mic round-trip (speak a
question, expect a sensible answer), ▶ read-aloud on a reply (karaoke
highlighting; "specific" must be pronounced correctly — espeak G2P), and
the + menu toggles (0°, 💭).

PDF note: `/v1/ingest` in the APE is text-in by design; the probe ingests
each PDF's paired `.txt`. The `.pdf` files exist to exercise the web UI's
client-side extraction path — that's why dragging them is the manual half.
